# Brief 5C - Android implementations of the engine ports (+ service)

Brief 5B built the engine against interfaces (`engine/Ports.kt`: `DownloadBackend`, `OutputStore`, `HistoryStore`) and a coroutine `DownloadQueue`. This brief implements those ports with real Android pieces and runs the queue inside a foreground service. No screens yet (5D). Read `AGENTS.md`, `core-spec/SPEC.md` (storage and no-duplicates rules), `engine/Ports.kt`, `engine/DownloadQueue.kt`, `engine/ProgressParser.kt`, `briefs/phase5-b-kotlin-engine.result.md`, and for behaviour reference `desktop/elisium_downloader/engine/runner.py`.

## Constraints you must respect
- Package `com.desolate.elisium`, new code under `.../android/`-style subpackages: `backend/`, `storage/`, `data/`, `service/`, `settings/`.
- No emulator, no adb. Unit-test everything that can run on the JVM (pure helpers, mapping, decision logic); the Android-API-bound code is verified by it **compiling**, by lint, and later by the owner on a real phone. Do NOT claim device behaviour works; say plainly what is only compile-verified.
- Verify youtubedl-android's real API from the library itself (unzip `~/.gradle` cached `youtubedl-android` `library-0.18.1` jar/aar and use `javap`, or its sources jar) BEFORE writing code. Do not rely on memory for method names or signatures.
- Dependencies you may add (stable only): Room (`androidx.room:room-runtime`, `room-ktx`, KSP plugin matching Kotlin 2.4.21, `room-compiler`), `androidx.datastore:datastore-preferences`, `androidx.work:work-runtime-ktx` only if you really use it. KSP is heavy on this 2-core machine: keep Room schemas small, run Gradle with the usual low-memory flags.
- Manifest: `FOREGROUND_SERVICE`, `FOREGROUND_SERVICE_DATA_SYNC`, `POST_NOTIFICATIONS`, `ACCESS_NETWORK_STATE`, `WRITE_EXTERNAL_STORAGE` with `android:maxSdkVersion="28"`. Set `android:allowBackup="false"` (cookies and history must not go to cloud backup) and add `dataExtractionRules`/`fullBackupContent` that exclude everything. Declare the service with `foregroundServiceType="dataSync"`.

## Build these
1. **`backend/YoutubeDlBackend.kt`** implements `DownloadBackend` using youtubedl-android. `probe(url)`: run `-J --no-download` (`--no-playlist` for single videos, `--flat-playlist` for playlist URLs; reuse the Python rule for "looks like a playlist" - port it as a small pure function with tests), parse stdout as JSON, throw `ProbeFailure(raw)` on non-zero exit or unparsable output; honour coroutine cancellation by destroying the process. `start(request, onProgress)`: builds the same argv as the desktop `build_command` (see runner.py): `-P home:<stagingDir>`, `-P temp:<stagingDir>/tmp`, `--download-archive`, `--no-overwrites`, `-o "%(title).150B [%(id)s].%(ext)s"`, `--continue`, `--newline`, the two `--progress-template` lines, retries, `-f`, optional `--limit-rate`, extra args, and `--print-to-file after_move:filepath <stagingDir>/<processId>.path`; also `--no-mtime`. Use the library's callback lines with `ProgressParser`; the raw log is accumulated; `await()` returns `DownloadOutcome` (read the `.path` file for `filePath`; detect `alreadyArchived` from the "has already been recorded in the archive" line and no path). `cancel()` calls the library's destroy-by-process-id. Keep `.part` files on cancel. Make pure parts (argv building, outcome interpretation, playlist detection) separate functions with JVM unit tests.
2. **`storage/MediaStoreOutputStore.kt`** implements `OutputStore`. API 29+: insert into `MediaStore.Downloads.EXTERNAL_CONTENT_URI` with `RELATIVE_PATH = "Download/Elisium/"`, `DISPLAY_NAME`, correct `MIME_TYPE` (from the extension), `IS_PENDING=1` while copying, then `IS_PENDING=0`; delete the staged file after a successful copy; return `PublishedFile(uriString, displayName)`; on failure delete the half-written row and return null. **No duplicates**: before inserting, query the Downloads collection for the same `DISPLAY_NAME` within `Download/Elisium/` and, if it exists, skip the insert and return the existing one (Android would otherwise silently rename to `name (1).mp4`). `existsFor(extractor, id)` queries for a display name containing `[<id>]` under `Download/Elisium/`. `existsAt(uri)` checks the URI still resolves. API 26-28: write straight into `Environment.getExternalStoragePublicDirectory(DIRECTORY_DOWNLOADS)/Elisium`, then notify the media scanner; needs the legacy permission (the UI asks for it in 5D). Put the decision logic (display-name/mime/skip rules) in a pure class with JVM tests; keep the Android calls thin. Also expose free-space check before a download starts (staging needs room for the file twice) as a pure helper.
3. **`data/` Room history**: `HistoryEntity` with the fields of `HistoryRecord`, `HistoryDao`, `AppDatabase` (version 1, `exportSchema=true` into `app/schemas`), and `RoomHistoryStore : HistoryStore` (synchronous methods are fine, called off the main thread). The queue itself runs on `Dispatchers.IO`-based scope. Provide a `LIKE` search that escapes `%`, `_`, `\`.
4. **`settings/SettingsRepository.kt`** (DataStore): concurrency (1-5, default 2), speed limit (null or a value like `2M`), preset id, wifi-only (default true), notify-on-done (default true). Pure validation functions shared with tests (port the desktop rules from `ui/settings.py`).
5. **`service/DownloadService.kt`** + **`ElisiumApp` wiring**: the `DownloadQueue` is an application-scoped singleton created in `ElisiumApp` after the engine is ready (use the `EngineState` already there). The service is a foreground service (type `dataSync`) with a notification channel "Downloads": ongoing notification with a summary ("2 downloading, 1 queued"), a progress bar for a single active item, actions **Pause all** / **Cancel all**; it starts when the queue gets active work and stops itself when idle, then posts a completion notification (batch "3 downloads finished"; failures use the plain-language error message) when `notify-on-done` is on. Wifi-only: if on and the network is not unmetered, hold items in `queued` and show the reason; resume when Wi-Fi returns (`ConnectivityManager.NetworkCallback`). Android 14+: start the foreground service from the user's action or from a notification action, handle `ForegroundServiceStartNotAllowedException` without crashing.
6. **Share intake plumbing (no UI)**: `MainActivity` handles `ACTION_SEND` with `text/plain`: extract the URL(s) from `EXTRA_TEXT` (pure function with tests: finds all http/https URLs in free text), and hands them to the queue's `add` (default preset). It shows nothing fancy yet: a toast-free minimal confirmation text on the existing screen ("Added 1 link"). Add the `<intent-filter>` for `SEND` + `text/plain`.
